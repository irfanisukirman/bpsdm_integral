1. Konvensi Umum & Arsitektur

Dokumen ini memetakan alur aplikasi per endpoint sistem BPSDM Integral (Laravel 12). Setiap endpoint disajikan dalam blok 6-bagian standar (lihat 1.7). Seluruh referensi merujuk kode sumber aktual: controller, model, service, routes/web.php, dan view Blade.

1.1 Struktur Rute & Middleware

  • Grup auth (routes/web.php ±baris 142) membungkus hampir seluruh rute admin/support: pelatihan, peserta, kehadiran, evaluasi, monitoring, dokumen, pengajar, forum, AI, aset, agenda, sertifikasi, TTE, magang, buku tamu, presensi kegiatan, profil, notifikasi.
  • Rute publik (di luar grup auth, blok "PUBLIC ROUTES"): landing page; global.search (±baris 82, controller memakai scope bila user login); documents.file.view & documents.file.download (±baris 93–94, otorisasi sepenuhnya di controller via authorizeFileAccess() — folder publik boleh tanpa login, privat wajib login+canView); documents.public (/share/folder/{token}), documents.public.file, documents.public.excel; verifikasi sertifikat/TTE; form publik buku tamu, presensi kegiatan, pendaftaran magang & rental; bantuan login.
  • Middleware global CekSetupPengajar (append grup web): narasumber yang belum memiliki record Pengajar selalu diarahkan ke pengajar.setup (kecuali halaman setup/logout).
  • Gate kustom (didefinisikan AppServiceProvider::boot()): superadmin-only (role === 'superadmin'), isParticipant (role === 'participant'), dan ticketing-access (role superadmin ATAU admin_bidang).
  • Rate limit pada beberapa rute publik (throttle:...) untuk mencegah penyalahgunaan form publik.

1.3 Pola Otorisasi & Scope Bidang

  • Sebagian besar endpoint memakai abort_unless(...) di dalam controller (tidak hanya middleware).
  • Pola umum cek pelatihan: authorizeTraining($training) = superadmin ATAU admin_bidang dengan bidang === training->bidang, selain itu 403.
  • Scope data admin_bidang: query selalu menambah where('bidang', Auth::user()->bidang); pengecualian hanya untuk superadmin (memilih bidang dari query string).
  • Segregasi tugas: verifikasi tindak lanjut monitoring tidak boleh dilakukan bidang tujuan temuan (anti konflik kepentingan).
  • Role lain (pengajar/participant/intern/mitra/penandatangan) diverifikasi per-aksi (mis. keanggotaan peserta, penugasan schedule, kepemilikan program).

1.7 Format Blok Alur Endpoint

Setiap endpoint disajikan sebagai blok 6-bagian:
1. URL/Route — metode + lintasan + nama route
2. Role/Auth — role, middleware, gate, pengecekan controller
3. Request fields — field validasi (required/type/limit)
4. Alur/Controller — logika controller & service step-by-step (transaksi DB, status, arsip)
5. Data — data yang disimpan/diambil (model & kolom)
6. Response — view / redirect / json / file download

A. TRAINING CONTROLLER (TrainingController.php)

Semua route berada dalam grup auth (routes/web.php:142, dan Route::resource('trainings', ...) di :317), kecuali dinyatakan lain.

A.1 index

1. URL/Route: GET /trainings — route name trainings.index

2. Role/Auth: Middleware auth. Scoping otomatis:
- Jika role != superadmin → query dibatasi where('bidang', Auth::user()->bidang) (line 43-45). Artinya admin bidang/bukan superadmin hanya melihat pelatihan bidangnya.

3. Request: Query params opsional: search, status (ongoing|upcoming|completed), year, model, sort (newest|oldest|name|start_soon).

4. Controller flow:
- Hitung $today = now('Asia/Jakarta')->toDateString().
- Susun $dashboardStats: total, ongoing (tgl_mulai <= today & tgl_selesai >= today), upcoming (tgl_mulai > today), completed (tgl_selesai < today), participants (sum dari withCount peserta ber-status approved).
- $years = distinct YEAR(tgl_mulai) desc.
- Query utama eager load schedules (urut date, start_time) + withCount:
- participants
- approved_participants_count (registration_status = approved)
- pending_participants_count (registration_status = pending)
- learning_schedules_count (schedule_type null ATAU != break).
- Filter when(...):
- search → nama_pelatihan/lokasi/bidang/angkatan LIKE %...%.
- status → match: ongoing, upcoming, completed (lihat definisi tanggal di atas).
- year → whereYear('tgl_mulai', $year).
- model → where('model', $request->model).
- Sort (match): default newest → orderByDesc('tgl_mulai')->orderByDesc('id'); oldest; name; start_soon → orderByRaw CASE WHEN tgl_selesai >= today THEN 0 ELSE 1 END, lalu tgl_mulai.
- paginate(12)->withQueryString().

5. Data fetched: Training + relasi schedules; withCount peserta approved/pending & jadwal learning; statistik dashboard; daftar tahun.

6. Response: View trainings.index dengan compact('trainings','dashboardStats','years').

18.2 Status Tiket, Reopen & Indikator SLA

  • Semua transisi lewat TicketingService::changeStatus → menulis TicketStatusHistory + LogHelper::record('Hotline', ...).
  • Alur: BARU → DIPROSES (respons pertama admin; set first_response_at bila masih null) ⇄ MENUNGGU_PENGGUNA; RESOLVED → CLOSED. CLOSED bersifat final (update status & balas ditolak dengan flash error).
  • Reopen: balasan pengguna saat MENUNGGU_PENGGUNA / RESOLVED otomatis kembali DIPROSES (note "Pengguna merespons" / "Pengguna membuka kembali tiket"); is_reopened=true, reopen_count+1, auto_close_at=null.
  • Auto-close: saat RESOLVED dan auto_close_at kosong → now()+72 jam (config ticketing.auto_close_hours); saat CLOSED → auto_close_at=null.
  • Indikator SLA (SlaService::calculateIndicator): selesai (RESOLVED/CLOSED), terlewati (lewat deadline), mendekati (sisa ≤50% total), aman, tidak_ditentukan (tanpa sla_resolve_hours).
